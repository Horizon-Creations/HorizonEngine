Creating, finding and removing entities. An entity is an integer id (see Entity ids). When a destroyed entity's slot is reused, the newcomer gets a different, larger id, so a kept id never points at a stranger; it just stops existing. Guard it with exists. exists(0) is false: 0 is what findByName returns when it finds nothing, even though it is also the scene root.

  • destroy takes the entity's children with it.
  • spawnClass and spawnClassRotated need the running game or play mode; they return 0 and log the reason when the class path is unknown or not an Entity class. The path is the class asset's content path, as in the Content Browser.
  • self, selfObject and the Ref rows (instance, owned, destroyObject) belong to HorizonCode objects. A Lua or Python script is not one, so self() and selfObject() always return 0 there; use self.entityId / self.entity_id.
  • Visibility only affects drawing. An entity with nothing to draw always reports getVisible = true, also right after setVisible(e, false).

Known issue: spawn creates no transform. The new entity has a name and a parent, but no Transform component, so setPosition, setRotation and setScale on it do nothing and getPosition returns 0, 0, 0 (measured on build 7d49d44f, also for the flat horizon.spawn). Until this is fixed, spawn a class with spawnClass, or give an entity its position by placing it in the scene.

saveState, hasSavedState and applySavedState store an entity's pose and visibility in the active save, keyed by the entity's stable UUID, so the same entity finds its state again after the scene is loaded anew. Three things must hold, and each missing one logs its own warning and returns false: the game is running (play mode or the packaged game), a save is active (save.create / save.load), and the entity has an enabled Save State component, whose checkboxes choose what is stored. Nothing is on disk until save.write.
