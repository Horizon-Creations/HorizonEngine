Which player controller drives which character. The references here are HorizonCode object references, not entity ids: a controller is an instance of a PlayerController class, a character an instance of a PlayerCharacter class. In Lua and Python they are plain integers, 0 meaning "none". To get from one to an entity use horizon.entity.owned(ref), the other way horizon.entity.instance(e).

  • controller() is the session's first controller, 0 in a project without a PlayerController class; character() is what it possesses. Both are 0 outside a play session.
  • A controller drives one character and a character has one controller: possess releases the controller's previous character and takes the new one away from any other controller. possess(0, …) does nothing.
  • The table only records numbers and checks none of them, so a wrong reference is stored as it is. Pass what controller() and entity.instance return.

A Lua or Python script is not a controller, so possession does not decide which script hears input: input actions reach every script (see Callbacks). What possession changes is which HorizonCode character graph receives the controller's input events, and which character the camera rig follows.
