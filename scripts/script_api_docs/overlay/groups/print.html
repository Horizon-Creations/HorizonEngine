Paper and PDF. toPdf writes a plain page of text itself; file hands an existing file to the system's print queue.

  • The PDF layout is fixed: A4, Courier 10 pt, 80 characters by 60 lines per page. Lines break at your newlines and at the last space that fits, pages when they are full. title becomes the document title in its properties. Characters of Latin-1 come through (Ä, é); every other one, the euro sign included, prints as ?. Missing folders on the way to the path are created.
  • toPdf always needs the permission Files outside the project, even for a relative path, which lands in the project's Saved folder like the fs rows. A path the user picked in a file dialog does not stand in for it (build 7d49d44f).
  • file and available use the system's lp, on macOS and Linux. On Windows both answer false. file needs Run other programs and answers true once the queue took the file, which says nothing about paper; a missing file is false.
