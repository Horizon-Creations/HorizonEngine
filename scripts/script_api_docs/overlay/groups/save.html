Savegames with a fixed shape. A save follows a SaveGame Template asset, which lists its fields and their defaults; the project's default template (Project Settings) is the one create uses. One save is active at a time and every field call works on it, in memory, until write puts it on disk as Saves/<id>.json in the game's data folder (see File System). write replaces the file in one step, so a crash leaves the old save or the new one, never half of each.

  • A save id may only contain A–Z a–z 0–9 _ -; anything else (a space, a dot) fails with a warning.
  • Each getter takes a default and returns it when there is no active save, the template has no such field, or the field has another type; the matching setter returns false. All three cases log a warning.
  • Numbers: a Float, Int or Enum field goes through setNumber / getNumber. An Int field drops the fraction toward zero (2.7 → 2, −2.7 → −2). A Float field keeps about seven digits: 0.1 comes back as 0.10000000149011612.
  • A struct field takes a value built with horizon.structs.<Name>() or read with getStruct (see Project Types). A plain table without __type is refused.
  • A save remembers its template, and load uses that one, not the project default. It keeps the fields the template still has and fills new ones with their defaults, so a save from an older version of the game still loads.
  • delete removes the file only. If it was the active save, it stays active, and the next write creates the file again; call close as well.
