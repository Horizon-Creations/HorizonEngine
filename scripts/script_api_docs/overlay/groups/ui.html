These rows work on entities that carry UI components: an element on a UI canvas in the scene, addressed by its entity id like any other entity. Widgets built in the Widget Designer are a different thing with their own ids, see Widget. From a script, pass the id: the element the script sits on is self.entityId (Python self.entity_id), another one is found once with horizon.entity.findByName.

  • Which component answers. The text rows need a UI Text component: setText on anything else does nothing and getText answers "". The colour is the Image tint, else the Text colour, else a Button's normal colour, in that order. An element with none of the three ignores setColor and reads as white (1, 1, 1, 1). Visibility, position and size belong to every element; an entity without UI answers false and 0, 0.
  • A colour is four numbers and a position or size two: setColor(e, 1, 0.5, 0, 1), setPosition(e, x, y). With three colour numbers Lua throws bad argument #5 and Python an IndexError. A missing visible reads as false in Lua, so the element disappears; Python throws.
  • Nothing is clamped or checked: a negative size is stored as it is.
  • pointerOverUI asks the widget layer: it is true while the pointer is over a widget, and while a widget dialog (widget.showModal) is open, wherever the pointer is. UI elements on a scene canvas do not count.

The value is written into the material asset in memory, not onto the element, the same as material.setParam. Two progress bars sharing one fill material show the same fill.
