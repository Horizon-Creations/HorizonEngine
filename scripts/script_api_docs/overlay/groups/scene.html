Every call that changes scenes is a request: it is queued and carried out at the start of the next frame, before any script's onUpdate, in the order it was made. So the code after load still runs in the old scene, and a zone you just loaded is not there yet: zonePosition returns 0, 0, 0 and zoneScene an empty string until the next frame. Show, hide and move requests made right after loadAdditive still apply to the new zone, because they queue behind it. Scene paths are relative to the project folder, for example Scenes/Level2.hescene.

  • Switching (load) replaces the whole scene. With hidden = true it only preloads the scene and its assets; hasPendingLevel turns true, and activate swaps it in without a loading hitch. A second hidden load replaces the pending one.
  • Zones (loadAdditive) add a scene next to the current one, at a world offset, and return a zone id at once. Zone ids count up from 1 and are never reused. A hidden zone is loaded and simulated but not drawn until showZone. A zone gets collision, and in the packaged game its scripts start when it arrives.
◆

In the editor's play mode zones work, but load and activate only log “runs in the packaged game” and keep the current scene. Leaving play mode removes every zone again.
