Relative paths point into the game's own data folder, the sandbox; .. cannot leave it. An absolute path works only for a file or folder the user picked in a file dialog, or when the project allows Files outside the project. Anything else fails with the call's “failed” value and a log line that names the path.

Where the sandbox is: in the editor, the Saved folder next to the project file. In the exported game, a per-user folder named after the project, HorizonCreations/<Project>/Saved under %APPDATA% on Windows, ~/Library/Application Support on macOS and ~/.local/share on Linux. Savegames (Saves/) and Preferences (Prefs.json) live there too, so fs.* can see and delete them.

  • writeText creates missing folders on the way. readText returns an empty string for a missing file.
  • copy never overwrites: it returns false when the target exists. rename does overwrite an existing file at the target, without asking.
  • remove deletes files only, never a folder. makeDir returns true when the folder already exists.
  • An empty path means the top of the sandbox for list and watch, and is refused everywhere else.
  • size and modified return -1 for anything that is not there, and size also for a folder. Both pass through a 32-bit float: sizes are exact up to 16 MB, and modified is up to 64 seconds off, the same issue as Date and Time. It can even lie a little in the future.
◆

watch reports changes through the HorizonCode event On File Changed on the GameInstance, and only in the exported game: the editor's play mode does not check watched paths, and scripts have no callback for it (see Events). From a script, read the file again on a timer and compare; modified is too coarse for that.
