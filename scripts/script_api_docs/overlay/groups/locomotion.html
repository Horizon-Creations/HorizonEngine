Tells a character what to do this frame. move, look, setMaxSpeed and setOrientToMovement write the entity's Movement component and do nothing, silently, on an entity without one; the jumps need a Character Controller and log when there is none. A Player Character gets both components automatically. The Movement system turns the request into velocity once per frame before physics steps.

  • move is an intent for one frame: call it every frame the character should walk. Two calls in the same frame add up, and the sum is cut back to length 1, so move(e, 1, 0, 0) twice still walks at the top speed, not twice it. Length 0.5 walks at half speed.
  • The direction is read as the Movement component's Move Direction Is setting says: World (the default) takes it as it is, Camera (the default for a Player Character) turns it by the main camera rig's heading, so (0, 0, -1) is "away from the camera". With an input action from the WASD preset, forward is move(e, x, 0, -y).
  • The Y component is dropped, but only after the length is cut to 1: move(e, 0.5, 3, 0) walks at 0.16 of the top speed. Pass 0 for Y.
  • look adds its yaw to the character's rotation; several calls in a frame add up. The pitch is accepted and ignored, nothing reads it (build 7d49d44f). Tilt the view through the camera rig with camera.addYawPitch.
  • setOrientToMovement(e, true) turns the character towards its travel direction at the component's turn rate (720°/s by default). Leave it off while look or a camera rig owns the facing, or the two fight each other.
  • jump uses the Character Controller's Jump Speed, jumpWith a speed of its own. Both return true only when the character left the ground; a second call in the same frame, a call in mid-air or a speed of 0 or less returns false. A jump within 0.12 s of walking off a ledge is still granted.
