SQLite databases, as files. open returns a handle for the other rows, 0 when it failed; at most 16 are open at once, and all close when the application ends. The path follows the fs rules: relative lands in the project's Saved folder, .. is refused, an absolute path needs the permission. There is no in-memory database: ":memory:" is an ordinary file name.

▲

open always needs the permission Files outside the project, even for a relative path inside the project. A file or folder the user picked in a dialog does not stand in for it, although it does for the fs rows and the editor's permission help says it would (build 7d49d44f). Without the permission open answers 0.

  • Values go behind ?, as a JSON array in params: '["Ada", 36.5]'. Strings, numbers, true/false (stored as 1/0) and null; a nested array or object is stored as its JSON text. Placeholders the array does not reach are NULL, and a params that is not an array is ignored. Python builds it with json.dumps. Lua has no JSON writer, and horizon.json.set* can overwrite array slots but not add them: start from a template such as '["", 0]' (see the example under query).
  • exec runs one statement. Of "INSERT …; INSERT …" only the first runs, and the answer is still true. exec on a SELECT runs it and throws the rows away.
  • query answers JSON text: an array with one object per row, keyed by column name. Integers come back as integers, REAL as floats (12.0), NULL and BLOB as null. An empty result and a failed query both give "[]"; lastError tells them apart. More than 10 000 rows are cut off, with a note in lastError.
  • lastError is SQLite's own message and empty after a call that worked. On a handle that is not open, exec is false, query "[]" and lastError empty. lastInsertId reads back ids above 2 147 483 647 as 2 147 483 647.
  • SQL cannot reach other files: ATTACH, VACUUM INTO and the pragmas that move SQLite's own files fail with “not authorized”.
