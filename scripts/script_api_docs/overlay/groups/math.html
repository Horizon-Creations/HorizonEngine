Pure functions over numbers: none of them changes anything, so they can be called anywhere and as often as needed. In a script the language's own math library does most of this too, and with more precision. horizon.math is for the results a HorizonCode graph would get, and for what the languages lack: lerp, clamp, the vector helpers and 32-bit bit operations.

  • Angles. sin, cos, tan and atan2 work in radians, while the engine's rotations are in degrees. radians and degrees convert between them; horizon.math.sin(90) is 0.894, not 1.
  • Precision. Every float crosses into the engine as a 32-bit number, about seven significant digits: normalize3(3, 0, 4) returns 0.6000000238…, 0, 0.8000000119…. Compare results with a tolerance, not with ==.
  • Vectors are spread like every other argument: length(x, y), distance3(ax, ay, az, bx, by, bz). normalize3 and cross return three numbers.
  • Bit operations (bitAnd to shiftRight) take and return 32-bit signed integers. Lua accepts an integer or a float with no fraction (6.0); 6.5 raises number has no integer representation. Python accepts only an int; any float raises TypeError. Results wrap at 32 bits: shiftLeft(1, 31) is −2147483648.
