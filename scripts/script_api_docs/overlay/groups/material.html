The named parameters of a node-graph material, the ones its Param nodes declare, read and written at runtime. Every parameter holds four numbers whatever the shader reads, so a scalar parameter is its first number. From Lua and Python, horizon.setMaterialParam(e, name, x [, y, z, w]) fills missing numbers with 0 and returns false when the entity has no Material component or the material declares no such parameter; horizon.getMaterialParam returns four zeros then.

▲

Known issue (build 7d49d44f): a set changes every entity with the same material. The value is written into the material asset in memory, not onto the entity. Set a parameter on one crate and every crate sharing its material changes. An entity that overrides the parameter in its Details panel keeps its override, and getParam does not see that override: it reads the asset. Until this is fixed, give an entity that needs its own value its own material asset.
