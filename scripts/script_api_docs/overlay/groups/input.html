Polling the keyboard, mouse, gamepad and the project's input actions. The engine takes one snapshot per frame, so every query gives the same answer for the rest of that frame. Only a running game or play mode fills it; in the editor outside play the values are stale. For one-shot reactions prefer the action callbacks (onInputPressed and friends) over polling.

  • Key names are SDL scancode names and case-sensitive: "W", "Space", "Left Shift", "Return", "Escape", "Up". keyDown("w") is always false.
  • Mouse buttons: 0 left, 1 right, 2 middle. mousePosition and mouseDelta return two numbers in Lua and a tuple (x, y) in Python.
  • Gamepad names are SDL's, not case-sensitive: buttons "a", "b", "x", "y", "leftshoulder", "dpup", "start"; axes "leftx", "lefty", "rightx", "righty", "lefttrigger", "righttrigger". "south" and "cross" are not names and read false. Sticks go −1…1 with Y positive downwards, triggers 0…1, and the deadzone is already applied.
  • Actions are looked up by the InputAction asset's name, case-sensitive; an unknown name reads false / 0. onUpdate runs before the actions are updated, so a poll from there sees the previous frame's state; actionPressed is still true for exactly one frame per press. The callbacks always carry the current frame. While the game is paused or the input mode is UI only, an action reads as released unless its asset has Fires while the game is paused ticked.

Input modes decide who receives input. The default is GameAndUI: both do, and a click on a widget is masked out of the game. GameOnly leaves the UI drawn but deaf. UIOnly gives the UI everything: the game then reads no keys, no mouse buttons and no gamepad (it reports disconnected), only mousePosition stays true. The mode does not show or hide the cursor; do that with the flat horizon.showCursor / hideCursor. Play mode starts in GameAndUI.

▲

Known issue: scrollDelta is always 0 in the running game and in play mode (build 7d49d44f). The per-frame snapshot is filled without the mouse wheel. Read the wheel through an input action instead: bind the Mouse Wheel source to an Axis action and poll it with actionAxis or handle onInputAxis.
