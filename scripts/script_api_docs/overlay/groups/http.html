Web requests that do not stop the game. get and post return a ticket at once; the answer is read later with that ticket. Both need the project permission Network access. Ticket 0 means the request never started: no permission, an empty URL, or a build without an HTTP backend (available). Plain http:// works as well as https://.

  • Scripts poll. HorizonCode gets On Http Response; a script does not, so it asks done(ticket) in onUpdate (see the example under get).
  • ok is about the connection, not the answer. A 404 is ok true with status 404. When the server was never reached, ok is false, the status 0 and error says why (“Could not connect to the server.”).
  • One request at a time. Requests go out one after another in the order they were made, each with a 5-second timeout, so a slow server delays the ones queued behind it. post with an empty content type sends application/json.
  • Answers are kept for a while, not forever. The last 32 are kept. An older one, a forgotten one and an unknown ticket all read the same: done false, status 0, empty body. Read an answer when it arrives, then forget it.
