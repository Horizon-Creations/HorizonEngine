The application around the game: its window, menu bar, tray icon, notifications and login item. These rows exist for desktop applications built with the engine and need a host that provides each piece. The exported application provides all of them. Play mode in the editor provides only quit (it stops play mode), size and requestRedraw; everything else logs “no … bound by the host” and does nothing.

▲

Known issue (build 7d49d44f): from Lua and Python only app.quit reaches the host. The script bridge passes a script the quit handler and nothing else, in the exported application as well. Every other row either logs “no … bound by the host” and does nothing, or answers its empty value: size 0, 0, isMaximized, notifyAvailable, autostart, menuItemEnabled and menuItemChecked false, notify false. requestRedraw is silent. Build window chrome, menus and the tray from a HorizonCode graph; its On Menu Item and On Tray Item events have no script counterpart either.

  • Ids and labels. A menu, menu entry or tray entry without an id is refused with a log line; an empty label shows the id. Adding a menu id twice is one menu. A shortcut that does not parse is dropped with a log line and the entry arrives without it; "Ctrl" means Command on a Mac.
  • Refused values. setSize with a side of 0 or less is ignored; notify with neither title nor text answers false. On macOS notify needs the packaged app.
  • setAutostart needs the project permission Run other programs; reading autostart needs none.
