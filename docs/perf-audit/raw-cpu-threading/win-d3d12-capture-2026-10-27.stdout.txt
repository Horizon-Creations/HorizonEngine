WaitFrame is NESTED inside Render, not a sibling: Render (Application.cpp:867) wraps
m_renderer->Render(), and WaitFrame (D3D12Renderer.cpp:13148) sits inside that call, inside
DrawViewportFrame. So the frame's own cpuMs already INCLUDES WaitFrame's wait time (which is why
Render's per-frame p50, 1.296 / 2.186 ms, is close to cpuMs p50, 1.32 / 2.21 ms, while GameLogicTick
etc. add only a little beside it). "% of frame" in the main doc uses WORK = cpuMs p50 minus
WaitFrame p50 (0.52 ms for s512_x4, 1.41 ms for ref10k) as the denominator, mirroring Step 1's Metal
methodology (NextDrawable subtracted) with the subtraction actually applied.
